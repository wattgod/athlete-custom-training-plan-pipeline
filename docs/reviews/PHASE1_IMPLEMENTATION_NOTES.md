## Decisions and deviations

- Fulfillment state, jobs, revisions, downloads, tokens, transitions, and
  status checks are keyed by immutable `order_id`. Athlete-keyed JSON files
  are lookup projections only. Intake subprocesses receive distinct
  `DATA_DIR/order-work/<order_id>/athletes` roots, so repeat/concurrent orders
  and colliding slugs do not share generated bytes.
- Legacy schema-v1 state is migrated lazily with write-new → verify →
  tombstone-old. All matching ledger orders are recorded as candidates and
  none is inferred. An authenticated `bind-legacy` endpoint records the
  coach's assertion; the quarantine blocker and old evidence remain intact.
  Old month-HMAC links cannot parse as typed-token/v1 links, so migration also
  fails closed for every pre-migration token.
- The transitional seal inventories every eager revision byte, including
  private ZWO and the customer bundle. The review ZIP contains only
  non-executable review material. Approval records both seal values; download
  and order-status paths re-verify them and the selected artifact bytes.
- Generation notifications are state-aware. Blocked/state-unavailable mail
  lists blocker policy and exposes only the coach review bundle. Until the
  Phase 2 review page exists, the Phase 1 "review materials" link is the same
  typed coach capability as the review-bundle link; it never exposes release
  artifacts or confirm controls.
- The post-render input version is
  `post_render/transitional-planir-tp-manifest/v1`. The validator treats
  PlanIR and `tp_manifest.json` as transitional reflections, not the content
  authority. `WEEKS_MISMATCH` remains in the normative `intake` namespace;
  post-render owns only the rules enumerated for it in C2.
- Explicit plan start dates inside the accepted grace window are honored.
  This is required for the deterministic W00/predates-generation distinction
  and also removes the date-dependent one-week truncation in the season API.
- The root pytest configuration uses importlib collection so identically named
  test packages can run together. Tests that require an uninitialized git
  submodule or the optional `flask_wtf` webapp dependency skip explicitly;
  all available tests run in the single full-suite command.
- No normative Phase 1 deviation or blocked implementation item remains.
